# CipherNest

CipherNest 是一款本地优先的跨平台密码生成与管理桌面应用，使用 Tauri 2、Rust 和 TypeScript 构建。界面采用暗色安全工具风格，目标平台为 Windows、macOS 和 Linux。

> **安全状态：未审计 beta（0.3.2）。** 当前实现包含真实的本地加密保险库和若干防护，但尚未经过独立安全审计，也没有达到可承诺“绝对安全”的程度。请先用非关键数据评估，并保留经过验证的加密备份。

## 已实现功能

- 创建、解锁和手动锁定一个本地保险库。
- 保存应用名称、用户名、密码、网站或主机地址、用途、备注、标签和收藏状态；地址按纯文本加密保存，可填写网址、主机名、`host:port` 或 `3389` 等标识。
- 条目列表只显示应用名称和更新时间；用户名、地址、用途、备注与标签默认遮罩，主动显示后按“敏感字段显示时长”自动重新隐藏。
- 搜索内容及 WebDAV 服务器、用户名同样默认遮罩；列表接口不会把用户名、用途或标签批量发送给界面进程。
- 搜索、筛选、排序、编辑和删除条目。
- 使用系统安全随机源生成 8–128 字符的密码，可选大小写字母、数字、符号、排除易混淆字符及“每类至少一个”。
- 在生成密码时同步填写应用名称、用户名、用途、网站或主机地址和标签，并一次性加密保存。
- 本地检查弱密码、重复密码和超过一年未更新的密码；不会查询在线泄露数据库。
- 可配置空闲自动锁定、窗口失焦锁定、敏感字段显示时长和剪贴板清除时长。
- 导出 `.cnvault` 加密备份；恢复采用“选择文件 → 输入备份主密码 → 预览 → 明确替换”的两阶段流程。
- 每次修改前自动保留旧的加密保险库快照，最多保留 10 份。
- Windows、macOS 和 Linux 均只支持主密码解锁，不提供设备便捷解锁旁路。
- 可选 WebDAV 手动端到端加密同步：默认关闭，只在保险库解锁且用户点击创建、加入或同步时连接；远端只保存由独立 256 位同步根密钥保护的不可变加密 snapshot 和加密 head。这里的“端到端加密”只覆盖正文机密性与完整性，不保证服务可用性、全局最新性或隐藏访问元数据。
- 应用从系统睡眠/休眠恢复时主动锁定保险库。
- 单实例运行、生产窗口关闭开发者工具、限制 WebView 内容安全策略。

当前**没有** CipherNest 账号或托管同步服务、后台自动同步、浏览器扩展、自动填充、保险库主密码恢复密钥、TOTP、遥测或自动更新器。WebDAV 的 CN1 同步恢复码只用于加入同一加密同步空间，不能重置主密码或单独恢复本地保险库。

## 安全设计摘要

| 项目 | 当前实现 |
| --- | --- |
| 主密码派生 | Argon2id v1.3，16 字节随机 salt，64 MiB 内存、3 次迭代、4 lanes，输出 256 位 KEK |
| 主密码规则 | 新主密码至少 12 个字符、最多 1024 UTF-8 字节；派生前执行 Unicode NFC 规范化 |
| 根密钥 | 系统 CSPRNG 生成的 256 位随机 Vault Root Key，不直接由主密码充当数据密钥；更改主密码时同时轮换 |
| 密钥包裹 | XChaCha20-Poly1305；主密码生成的 KEK 只用于包裹根密钥 |
| 正文加密 | HKDF-SHA-256 从根密钥派生正文密钥，XChaCha20-Poly1305 使用每次新生成的 24 字节 nonce |
| 完整性 | 密钥包裹和正文均使用 AEAD；AAD 绑定格式版本、vault ID、KDF 参数或 generation |
| 磁盘写入 | 最大文件大小 16 MiB；同目录原子替换；Unix 新建目录/文件尝试使用 `0700`/`0600` |
| 随机密码 | Rust 后端调用操作系统随机源，并使用拒绝采样避免取模偏差 |
| 解锁方式 | Windows、macOS 和 Linux 均只接受主密码；没有设备认证替代通道、TOTP 解锁或主密码恢复密钥 |
| 可选 WebDAV 同步 | 默认关闭、仅手动触发、锁定态不发起新请求；独立随机 256 位 CN1 同步根密钥，XChaCha20-Poly1305 加密 snapshot/head，SHA-256 父链与强 ETag/`If-Match` 并发控制；WebDAV 按不可信密文存储处理 |
| 内存 | Rust 中根密钥和部分敏感缓冲区在释放时尽力清零；解锁期间完整保险库仍会存在于进程内存中 |
| 网络 | 未配置同步时正式应用不发起业务网络请求；配置后只有用户在解锁态创建、加入或点击 WebDAV 同步时发起请求。途中锁定时已开始的密文请求可能收尾，但不得提交本地状态。没有账号、遥测、远程内容、后台同步或更新网络请求 |

保险库文件外层是 JSON envelope，因此攻击者仍可看到格式版本、随机 vault ID、generation、KDF 参数、密文长度和大致文件大小；应用名称、账号、网站或主机地址、用途、备注、密码和设置位于认证加密的正文中。

安全性不依赖隐藏算法或阻止反编译。应用中没有通用主密钥、硬编码主密码或全局 pepper；反编译和复制锁定文件不会直接还原明文。但本地保险库的 salt 与认证密文允许不受 UI 限速约束的离线主密码猜测，因此仍必须使用不可预测且不复用的强主密码，并启用操作系统全盘加密。远端 WebDAV 密文由独立高熵同步根密钥保护，不是主密码校验器；相反，泄漏 CN1 恢复码后，只要攻击者也能取得远端对象，就等同于泄漏该同步空间的历史解密能力。

完整边界和剩余风险见 [威胁模型](docs/THREAT_MODEL.md)，WebDAV 协议与限制见 [同步设计](docs/SYNC_DESIGN.md)，漏洞报告方式见 [安全政策](SECURITY.md)。

## 使用方式

### 第一次启动

1. 创建至少 12 个字符的主密码；更推荐使用 5–7 个随机且互不相关的词。
2. 请离线记住或妥善保存主密码。当前版本没有保险库主密码恢复密钥、客服后门或密码重置功能；WebDAV 同步恢复码不能代替主密码。
3. 创建后立即导出一份 `.cnvault` 加密备份，并在另一位置验证可恢复性。

### 生成并保存密码

打开密码生成器，选择长度和字符集，同时填写应用名称、用户名、用途等信息。点击保存后，这些字段和密码会作为同一条目写入加密保险库。默认生成长度为 20 个字符，并要求每个已选字符类别至少出现一次。

### 锁定与剪贴板

- 后端默认空闲 5 分钟锁定；设置允许 1–120 分钟，界面提供常用选项。
- 窗口失焦时总会重新遮罩已显示的密码；只有启用“窗口失焦时锁定”后才会同时锁定保险库。
- 应用收到系统睡眠/休眠后的恢复事件时会锁定；这仍不能替代操作系统锁屏和全盘加密。
- 后端默认在 20 秒后清除仍与本应用复制内容相同的剪贴板文本，可选 10、20、30 或 60 秒。
- 剪贴板是系统共享资源。当前版本没有阻止 Windows 剪贴板历史、macOS Universal Clipboard 或第三方剪贴板管理器，因此复制操作不能视为安全通道。

### 解锁方式

- 从 0.3.2 起，Windows、macOS 和 Linux 均只支持主密码解锁，设置中不提供设备便捷解锁开关。
- 主密码始终是解密保险库的唯一凭据；遗忘后无法由设备认证、Authenticator/TOTP、同步恢复码、服务器或维护者重置。
- 从旧版本升级时，第一次解锁必须输入主密码。成功验证后，应用会先移除旧设备 slot，再保留加密快照、生成全新的 VRK 并重新加密当前正文；若后续迁移无法安全写入，保险库不会交付解锁会话，并会在下次主密码解锁时重试。平台钥匙串或认证器内的旧凭据可能成为当前版本不再调用的孤立项，但它们已与迁移后的新 VRK 断开。旧附属记录不是备份，也不会让 0.3.2 绕过主密码；旧版保险库、旧 device slot 与原设备凭据组成的完整历史仍必须妥善保护。

### 备份与恢复

- “导出加密备份”复制当前认证加密的 envelope，不产生明文导出。
- 恢复分为两个阶段：先选择文件并用该备份自己的主密码完整解密、验证，再显示文件名、条目数、更新时间、generation 和保险库标识摘要；只有用户明确确认后才替换当前保险库。替换前还会自动备份当前版本。若来源是旧版备份，原文件不会被改写，但已验证的待恢复候选会在确认前换用全新随机 VRK 并转换为仅主密码格式。
- 加密导出只包含主密码保护的保险库 envelope；迁移或恢复必须使用备份所属的主密码。
- 更改主密码会为当前保险库生成新 VRK 并重新加密正文；旧主密码不能解密轮换后的当前正文。
- 修改或删除的秘密仍可能存在于旧备份中。轮换不会改写已经导出或被攻击者复制的旧数据，旧备份仍可能由其原主密码解锁。
- 自动备份通常与主保险库位于同一个应用数据目录，只能防部分误操作或损坏，不能替代异盘/离线灾难恢复。

### 可选 WebDAV 手动同步

- 在设置中创建新同步空间，或凭 WebDAV 地址、用户名、应用专用密码和 `CN1.` 同步恢复码加入已有空间。建议使用专用 WebDAV 目录和可单独撤销的应用密码。
- 同步恢复码包含独立随机 256 位同步根密钥。请离线保存并与 WebDAV 密码分开；泄漏后应创建全新的同步空间，而不是只在某一设备停用。
- 远端同步对象只保存不可变加密 snapshot 和加密 head；不会包含主密码、KDF、VRK、本地设置、旧版设备认证记录或 WebDAV 凭据。应用密码只作为 HTTPS Authorization 凭据发送给用户配置的服务器。
- 日常同步使用本地 base 做三方合并。两端同时修改同一条目，或发生“删除与修改”冲突时，会保留带“同步冲突”标记的副本，而不是静默覆盖。
- 下载或合并只更新条目与删除墓碑，保留当前设备的安全设置；本地写入前仍会创建加密自动备份。
- 加入空间的预览由后端签发 5 分钟有效、单次使用的不透明 token，绑定当前保险库会话、规范化端点、用户名、sync ID、远端 snapshot 精确哈希和 sequence。确认加入时会重新获取并要求这些值完全一致；锁定、过期、重复使用或远端 head 已变化都会拒绝应用，要求重新预览。这只保证“应用的是刚才预览的那个合法 snapshot”，不能消除首次加入的 TOFU。
- 已保存 checkpoint 的设备会在最多 256 个 snapshot、总计 90 秒的预算内验证远端父哈希链；全新设备首次加入属于 TOFU，无法只靠恢复码证明看到的是最新版本。服务器仍可删除、延迟或拒绝数据，并看到文件名、数量、大小、时间、IP 和账号等元数据。
- 更改主密码会轮换本地 VRK，并用新 VRK 重新保护本机同步 sidecar；它**不会**轮换共享的同步根密钥、撤销 WebDAV 应用密码或清除远端历史。若怀疑设备、本机旧数据、WebDAV 凭据或 CN1 恢复码泄漏，应同时撤销旧 WebDAV 应用密码，并从可信设备创建全新的同步空间与恢复码后迁移。
- 停止当前设备同步只删除本地配置，不删除远端历史。不可变 snapshot 在 0.3.2 中不会自动垃圾回收。

不要把活动中的 `vault.cnvault` 直接放进云盘并让多台设备同时打开；请使用应用内 WebDAV 同步，或用显式加密备份迁移。同步不能替代异盘/离线备份。完整协议边界见[同步设计](docs/SYNC_DESIGN.md)。

## 数据位置

程序通过 Tauri 的 `app_data_dir` 保存数据，应用标识符为 `com.ciphernest.vault`：

```text
<应用数据目录>/vault.cnvault
<应用数据目录>/vault.cnvault.sync           # 仅配置 WebDAV 后存在，内容整体加密
<应用数据目录>/backups/auto-<vault-id>-<20位generation>.cnvault
<应用数据目录>/backups/auto-<vault-id>-<20位generation>-<sha256>[-<uuid>].cnvault  # 同代不同内容时
```

`.sync` 由当前 VRK 派生的独立密钥认证加密，内部包含 WebDAV 应用密码、同步根密钥、checkpoint 和三方合并 base；它不会随 `.cnvault` 导出。未启用同步时不会依赖此附属文件。旧版本可能遗留 `.devices` 或 `.device-auth` 文件；0.3.2 不把它们读取为解锁凭据，并在首次主密码迁移或相关保险库生命周期操作中清理本地附属文件。操作系统钥匙串或 Windows 平台认证器中的孤立凭据不由 0.3.2 枚举或调用。自动备份在基础文件名已存在时先比较精确规范字节：完全相同则不重复写；同一 vault ID/generation 却内容不同则使用内容 SHA-256（极端路径冲突时再加随机 UUID）后缀另存，避免恢复分支重新经过同一 generation 时静默漏掉新快照。所有这些名称仍共同计入最多 10 份的轮换上限。

同步提交、VRK 轮换或恢复事务期间可能短暂出现 `.sync.next`、`.sync.restore-hold` 等恢复候选；它们同样是认证密文，不是便携备份，应用会在成功、回滚或下次读取时协调/清理。不要手工移动或编辑这些文件。

具体父目录由操作系统和用户环境决定，通常位于：

- macOS：`~/Library/Application Support/com.ciphernest.vault/`
- Windows：`%APPDATA%\com.ciphernest.vault\`
- Linux：`$XDG_DATA_HOME/com.ciphernest.vault/`，未设置时通常在 `~/.local/share/`

Windows 覆盖安装沿用相同应用标识符和数据目录。升级前建议导出一份加密备份；如果安装流程调用旧版卸载器并显示“删除应用数据”选项，请勿勾选，否则保险库及本机同步配置可能被删除。安装完成后先用原主密码解锁并核对条目，再进行其他操作。

不要手工编辑保险库。移动数据时优先使用应用内的加密备份功能。

## 从源码运行

要求：

- Node.js 24.x（仓库包含 `.nvmrc`）
- pnpm 10.12.1
- Rust stable；crate 声明的最低 Rust 版本为 1.85
- 对应平台的 Tauri 2 系统依赖

安装 JavaScript 依赖并运行开发版：

```bash
corepack enable
corepack prepare pnpm@10.12.1 --activate
pnpm install
pnpm desktop:dev
```

执行当前已有的前端构建、Rust 测试，并构建当前平台安装包：

```bash
pnpm build
cargo test --manifest-path src-tauri/Cargo.toml
pnpm tauri build
```

构建产物位于 `src-tauri/target/release/bundle/`。Tauri 桌面包通常应在对应目标操作系统上构建，不建议把这里的命令理解为已经配置好的任意平台交叉编译。

`pnpm check` 会执行前端安全边界测试、前端类型/生产构建和 Rust 测试；`pnpm desktop:build` 会在测试通过后打包当前平台。当前前端测试主要验证 CSP、前端不直接使用浏览器持久化/网络/弱随机数/不安全 HTML API，以及敏感操作必须委托 Rust；WebDAV 请求由 Rust 后端执行。这仍不能替代完整 UI、IPC、协议和三平台安全测试。

### macOS

安装 Xcode Command Line Tools，然后执行上述命令。配置的最低系统版本是 macOS 10.15，`tauri.conf.json` 已启用 hardened runtime 和 ad-hoc 签名；当前仓库没有配置可信的 Developer ID 签名或 notarization 凭据，因此仍会触发 Gatekeeper 警告。macOS 版本仅支持主密码解锁。

### Windows

安装 Microsoft C++ Build Tools、Windows SDK、WebView2 Runtime 和 Rust MSVC 工具链，然后执行上述命令。当前仓库没有配置 Authenticode 证书。Windows 版本仅支持主密码解锁。

### Linux（Debian/Ubuntu）

除 Node/Rust 外，安装 Tauri/WebKitGTK 构建依赖：

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential curl wget file libssl-dev \
  libwebkit2gtk-4.1-dev libayatana-appindicator3-dev \
  librsvg2-dev libxdo-dev patchelf
```

然后执行 `pnpm desktop:build`。其他发行版请使用等价的软件包。

仓库中的 CI 工作流配置了 macOS 14、Windows Server 2022 和 Ubuntu 22.04 的测试/编译矩阵；打包工作流显式指定并校验 macOS ARM64、Windows x86-64 和 Linux x86-64 目标，要求 DMG、NSIS EXE、AppImage、DEB 四件套及 SHA-256 清单齐全。macOS 包仅为 ad-hoc 签名，Windows/Linux 没有可信发布签名，三个平台都不能视为已完成发布身份验证。工作流存在也不等于某个提交已经通过实跑；必须以对应 GitHub Actions 结果与产物架构校验为准。

## 当前限制

- 这是未审计 beta，不适合作为唯一的关键凭据副本。
- 解锁时完整保险库在 Rust 进程内存中；选中的条目和生成结果会进入 WebView/JavaScript 内存。
- 没有内存锁页、崩溃转储抑制、独立硬件安全密钥、设备便捷解锁或保险库主密码恢复密钥；三个平台都只接受主密码。
- 应用会在收到系统恢复事件时锁定，但没有跨平台独立验证所有锁屏、休眠、用户切换和异常挂起路径；自动锁仍依赖应用活动计时，失焦锁需要用户开启。
- `generation` 能绑定当前 envelope 的头和密文，但没有外部单调锚点，完整旧文件回滚无法被可靠识别。
- WebDAV 是可选的不可信存储边界：服务端可删除、延迟、回滚或拒绝数据；只有持有已保存 checkpoint 的设备可检测部分回滚，全新加入和整个本地数据同时回滚仍有盲区。
- 离线设备若落后超过 256 个 snapshot，或父链验证累计超过 90 秒，会失败关闭；删除配置后重新加入会失去旧 checkpoint，并重新进入 TOFU。
- CN1 v1 所有设备共享同步根密钥，没有逐设备密码学撤销；远端不可变历史不自动清理，并泄露大小、数量、时间、IP 和账号等元数据。
- 更改本地主密码不会轮换 CN1 同步根密钥，也不会撤销 WebDAV 应用密码；怀疑同步秘密或设备泄漏时必须撤销服务器凭据并迁移到新同步空间。
- 当前尚未完成至少一个真实 WebDAV 提供商的端到端互操作验证；内置能力探测只能验证当前请求看到的部分条件请求语义，不能替代真实服务测试或独立协议审计。
- Windows 文件 ACL 依赖应用数据目录继承权限；代码没有显式设置独立 ACL。
- 安全检查是本地启发式提示，不是泄露数据库检查或密码学证明。
- 自动备份与主文件通常在同一磁盘；旧备份保留历史秘密。
- 更新器和发布签名尚未配置；不要安装来源不明的二进制包。
- 当前前端只有少量安全边界回归测试，尚无完整 UI、无障碍和 IPC 端到端自动化覆盖。
- 当前 RustSec 扫描未报告已知 `vulnerability` 类条目，但 Linux GTK3 传递依赖仍包含一项 `glib` 不健全实现公告和若干停止维护警告；Linux 包在上游依赖迁移或风险复核完成前只能视为 beta。

## 发布前最低要求

发布者应确保 `pnpm check` 和三平台 CI 全部通过，检查依赖锁定与漏洞报告，配置平台代码签名，并在宣传为生产级密码管理器前安排独立密码学与桌面安全审计。
