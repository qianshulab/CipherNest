# CN2 WebDAV 多设备同步设计

本文描述当前实现的 CN2 协议。CN2 在已有的 HTTPS WebDAV collection 中保存追加式加密事件，各设备在本机重放事件并合并条目与删除记录。旧版 CN1 的可变 head、snapshot、强 ETag 和条件写入协议见[旧版同步设计](SYNC_DESIGN.md)；CN2 与 CN1 的远端对象和本机配置彼此独立。

## 1. 协议边界

CN2 的收敛条件是：参与设备最终能够从诚实的服务器读到同一空间的完整事件集合。客户端不要求服务器提供原子比较并交换，但仍要求目录查询、普通对象读取和创建可正常工作。每个写入设备只创建以内容哈希命名的新对象，不更新共享指针，也不自动删除历史事件。

服务器是不可信的存储方。客户端对列出的对象核对文件名中的哈希、解密认证并验证事件图；缺失的已知事件、设备计数器分叉和缺失的因果依赖会使同步失败。服务器仍可隐藏尚未被本机见过的合法事件、对不同设备提供不同视图、延迟或拒绝服务。全新设备首次加入没有历史检查点，必须与可信设备核对远端概览。同步不能代替独立的加密备份。

## 2. 标识、密钥与对象

创建空间时生成规范形式的随机 UUID `space_id`、随机 256 位 Sync Root Key 和本机随机 UUID `device_id`。恢复码采用以下格式，密钥使用无填充的 base64url：

```text
CN2.<space_id>.<base64url-32-byte-root-key>
```

恢复码与本地主密码、Argon2id 参数、保险库 Vault Root Key（VRK）分离。它包含解密及构造该空间事件所需的共享秘密；WebDAV 用户名和应用密码仍须另行提供。恢复码不能重置保险库主密码。

同一目录中的 CN2 事件名为：

```text
ciphernest-<space_id>-event-<sha256>.cnevt
```

`sha256` 是**完整加密对象文件字节**的 SHA-256 小写十六进制值，不是明文哈希。读取时只选取与当前 `space_id` 精确匹配的对象名，并核对实际字节与文件名。不同同步空间可以使用同一 collection，但客户端只处理自己的对象。对象外层是 JSON：

| 字段 | 含义 |
| --- | --- |
| `format` | 固定值 `CipherNestSyncEvent` |
| `version` | 数值 `2` |
| `nonce` | 每次加密新生成的 24 字节 nonce，无填充 base64url |
| `ciphertext` | 含认证标签的密文，无填充 base64url |

解密后的 JSON 使用 camelCase 字段名，拒绝未知字段。事件正文包含 `protocolVersion`、`spaceId`、`genesis`、`deviceId`、`counter`、`prevEventHash`、`observedHeads`、`createdAt` 和 `mutations`。`observedHeads` 是创建该事件时已接受的“设备 ID → 事件哈希”映射；`mutations` 中每项包含操作父引用 `parents` 和一条以 `entry` 或 `deleted` 标记的记录。`createdAt` 为 Unix 毫秒时间戳。条目及墓碑在密文中；时间戳用于状态展示和记录内容，不用于冲突的最后写入者裁决。

密钥派生和认证参数如下：

| 用途 | 输入与参数 |
| --- | --- |
| 远端事件密钥 | HKDF-SHA-256；输入密钥为 Sync Root Key，salt 为 UTF-8 `space_id`，info 为 `CipherNest sync-v2 event` |
| 远端事件 AEAD | XChaCha20-Poly1305；AAD 为 `CipherNest\0SYNC_EVENT\0v2\0<space_id>` |
| 本机配置密钥 | HKDF-SHA-256；输入密钥为当前 VRK，salt 为 UTF-8 vault ID，info 为 `CipherNest local-sync-state-v2` |
| 本机配置 AEAD | XChaCha20-Poly1305；AAD 为 `CipherNest\0LOCAL_SYNC_STATE\0v2\0<vault-id>` |

`\0` 表示单个 NUL 字节。两类对象均使用随机 24 字节 nonce。本机 `vault.cnvault.sync-v2` 的外层 JSON 为 `CipherNestLocalSyncV2State`、版本 2、vault ID、nonce 和密文。加密正文保存 WebDAV 地址及凭据、共享密钥、本机设备 ID 和计数器、各设备检查点、上次接受的内容与记录头、最近本机 generation、最近同步时间、自动同步状态及可能尚未确认上传的事件。事务期间还可能存在加密的 `vault.cnvault.sync-v2.next` 恢复候选。

远端事件不包含主密码、KDF salt 或参数、KEK、VRK、完整本地保险库信封、WebDAV 凭据、同步 sidecar、应用设置、备份状态或旧版设备认证记录。本机配置受 VRK 保护；更改主密码并轮换 VRK 时会重新加密当前配置，但不会轮换共享 Sync Root Key、WebDAV 应用密码或已上传事件。

## 3. 事件图与设备计数器

创建空间产生唯一的 `genesis` 事件：写入设备计数器为 1，没有前驱事件和已观察头；初始保险库即使为空也可以有一个无修改的 genesis。后来每个设备有独立、从 1 开始且无空洞的计数器链。除该设备第一个事件外，`prevEventHash` 必须指向同设备上一个计数器的事件，`observedHeads` 中该设备的头也必须与它相同。新设备的首个非 genesis 事件必须观察到至少一个已有设备头。

每个 `observedHeads` 引用必须对应本次获取的真实事件和正确设备，事件间依赖不得成环。操作父引用使用 `<event-hash>:<mutation-index>`；为冲突副本保留的隐式来源使用 `i:<event-hash>:<mutation-index>`。父操作必须属于同一记录 ID（隐式来源除外），其来源事件不能晚于写入者声明已观察到的相应设备头。每个事件内同一记录 ID 最多修改一次。

完整重放还要求只有一个 genesis，所有设备流的计数器连续、前驱哈希相符；同一设备同一计数器出现分叉或任何已声明依赖缺失时失败。`device_id` 和计数器用于一致性检查，不是逐设备签名或授权机制。所有持有共享恢复码并能写入该 WebDAV 目录的人都可构造认证事件；CN2 没有逐设备密码学撤销。

## 4. 发布、拉取与合并

创建空间时先读取当前 `space_id` 的事件列表，要求为空；随后**先在本机加密 sidecar 持久化 pending 事件**，再尝试上传。日常同步也先获取并验证完整远端事件集合，再根据上次接受的 `base_content` 与当前本机内容生成待上传修改。记录从 base 消失而没有显式墓碑时会拒绝发布，不能把缺失猜测成删除。

待上传事件一经生成，其加密字节、文件名、来源 generation 和来源内容都保存在 sidecar。上传前检查把它加入已读取事件集合后是否仍可有效重放并满足容量上限。客户端先 `GET` 目标名：若已有对象与待上传字节完全一致，视为此前上传已完成；若不同则失败。不存在时执行普通 `PUT`，随后 `GET` 并逐字节核对。上传完成后推进本机设备计数器和因果基线；若本机在待上传事件形成后又有更新，会按新的基线准备后续事件。最后重新获取远端集合、重放并提交合并结果。

加入设备时，先认证读取远端事件并展示概览。预览 token 有效期为 5 分钟且仅可使用一次，绑定协议版本、端点、用户名、空间 ID、本机 vault/session/generation、事件数量和排序后事件哈希集合的指纹。指纹为 SHA-256：按事件名排序，对每个文件名中的 64 字符哈希依次追加一个换行字节后计算。确认时重新拉取并核对；事件集合或绑定的本机状态变化需重新预览。本机已有条目或墓碑时，默认合并；选择以远端替换本机需额外确认。首次合并没有共同祖先：相同 ID、相同内容去重；本机不同的记录以空父引用加入事件，由重放规则保留冲突。

重放按记录 ID 收集全部操作版本。一个操作列出的父操作被它取代；未被取代的版本构成该记录的当前头。本机后续编辑会引用上次认证视图中该 ID 的**全部当前头**，使已见的并发版本都成为新操作的因果父项。若有多个当前头，优先选删除记录；同类之间按操作 ID 的字典序确定一个主版本。这一确定性选择只决定原 ID 的内容，不以设备时钟或到达顺序做最后写入者覆盖。

不同内容的并发条目版本若未成为主版本，会产生确定性冲突副本。重放按因果顺序检查历史前缀：一旦某条目版本曾是需要保留的冲突方，即使后来原 ID 被再次编辑、两个头都被取代，该副本仍留在结果中。副本 ID 由 `SHA-256("CipherNest CN2 conflict copy\0" || space_id || "\0" || source_op_id)` 的前 16 字节设置 UUID 版本／变体位得到；标题附加“（同步冲突）”，标签空间允许时加入“同步冲突”。一方删除、另一方修改时，原 ID 保留墓碑，修改版成为冲突副本。相同内容的并发版本不重复生成副本；多个删除版本只保留一个主墓碑。冲突副本后续的显式编辑或删除会引用其隐式来源，避免重新重放时丢失该副本的历史。条目上限和墓碑上限仍适用，冲突副本须由用户核对。

## 5. 检查点、崩溃恢复与自动运行

sidecar 的 `seen` 为每个已见设备保存最新计数器和事件哈希。后续完整拉取必须仍包含各设备此前接受的**精确事件**，且计数器不得倒退。本机设备流若领先于本机已确认计数器，只有与持久化 pending 完全一致的下一个事件可接受；否则按分叉或本机状态回滚处理。本机保险库 generation 低于 sidecar 最近记录值时拒绝同步；generation 相同但内容与已接受基线或 pending 来源不符时也拒绝。

获取到的远端内容只有在本机保险库持久化后才能推进检查点。需要同时更改保险库和 sidecar 时，先写加密 `.sync-v2.next` 候选，再写保险库，最后更新正式 sidecar 并移除候选。重新打开时按 vault generation 与已认证候选决定是否恢复；候选与正式状态矛盾时拒绝猜测。已持久化的 pending 使中断的 `PUT` 可以通过精确回读安全重试。锁定、会话切换或并发本地保存后，旧网络结果还必须通过 vault ID、session ID、generation 和 sidecar 摘要校验，才能提交本机状态。

新建和加入的 CN2 配置默认开启自动同步。解锁和本机保存后约 3 秒安排一次检查，持续解锁时约每 90 秒轮询；手动操作优先于后台检查。没有本地变化和 pending，且上次完整认证结果已持久化、距今不到 1 小时时，后台检查可以只比较目录中事件名的集合指纹；相同表示本轮不改动本机状态。满 1 小时后的下一次自动检查须完整拉取，才能发现对象被原位替换等异常；手动同步始终执行完整拉取。

普通网络失败留下警告，后续自动检查可重试；本地检查点、事件认证或容量等安全错误会暂停自动同步，等待用户核对并手动处理。手动成功接受远端视图会清除暂停和警告。锁定状态不启动新的同步；锁定期间完成的旧请求不得提交到新会话。

## 6. 传输要求与资源上限

端点必须是已存在、以 `/` 结尾的 HTTPS collection。URL 不接受内嵌 userinfo、query、fragment、编码的斜杠或反斜杠。客户端用 `PROPFIND Depth: 0` 确认 collection，用 `Depth: 1` 列举事件，普通 `GET` 读取、普通 `PUT` 创建。HTTP Basic 凭据只经验证的 HTTPS 发送；客户端要求 TLS 1.2 或更高、系统信任的证书，不跟随重定向，也不使用代理。请求带 `Cache-Control: no-cache, no-store` 和 `Accept-Encoding: identity`；连接超时为 10 秒，请求超时为 45 秒。

| 资源 | 当前上限 |
| --- | ---: |
| 单个加密事件文件及事件明文 | 各 32 MiB |
| 一次完整拉取的事件密文总量 | 256 MiB |
| 事件目录列表响应 | 16 MiB |
| 事件数量 | 40,000 |
| 全部事件的修改操作数 | 200,000 |
| 写入设备数 | 64 |
| 单事件操作数 | 30,000 |
| 本机加密 sidecar 文件及明文 | 各 96 MiB |
| 合并后的条目／墓碑 | 10,000／20,000 |

列举、下载和重放都执行大小及结构校验；发布前也检查新增事件后的结果。但普通 WebDAV 没有跨设备原子的容量事务，并发写入可能在各自通过检查后使空间超过读取上限。达到上限时应保留各设备本机数据和独立备份，核对未同步修改后迁移到新空间。CN2 当前没有远端垃圾回收、历史版本浏览或整库恢复界面。

## 7. 安全限制

- 文件名哈希和 AEAD 能发现收到的对象被替换或损坏，不能证明服务器列出了所有尚未见过的对象。新设备首次加入仍是信任首次所见；协议没有内建的全局最新性证明，应与可信设备核对。
- 已保存的设备检查点能发现自己见过的事件被删除、隐藏或替换；如果攻击者同时回滚本机保险库及 sidecar，或让设备长期看到一致但不完整的分叉，协议没有外部单调锚点保证发现。
- 服务器仍能观察 WebDAV 账号、IP、访问时间、空间 ID、文件名、数量、大小、ETag 和请求模式。正文加密不隐藏这些元数据。
- 停用本机同步只删除本机配置，不删除远端事件，也不撤销其他持码设备。主密码变更同样不撤销共享恢复码或 WebDAV 应用密码。怀疑泄漏时须在服务端撤销旧凭据，并在核对数据后迁移到新的同步空间；已流出的旧密文仍可能被旧密钥解密。
- 同步会传播删除和冲突副本；WebDAV 服务端的长期保留及可用性不受客户端保证。应定期导出到独立介质。

实现位于 [`sync_v2.rs`](../src-tauri/src/sync_v2.rs)；命令编排和自动调度位于 [`commands.rs`](../src-tauri/src/commands.rs)。操作步骤见 [WebDAV 使用指南](WEBDAV.md)，安全边界见 [威胁模型](THREAT_MODEL.md)。
