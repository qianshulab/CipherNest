# WebDAV 使用指南

CipherNest 的“WebDAV 多设备同步”通过已有的 HTTPS WebDAV 目录在设备间传递已保存的条目修改和删除。服务器只保存加密数据；同步恢复码需单独保管。旧版 CN1 同步及单向远端备份仍可在设置中的折叠入口使用。

## 准备 WebDAV 目录

1. 在 WebDAV 服务上创建一个专用目录，为同步账号授予查询、读取和创建文件的权限。若还使用旧版远端备份的连接测试，账号也需删除测试文件的权限。建议使用可单独撤销的应用专用密码。
2. 准备以 `/` 结尾的完整 `https://` 目录地址。用户名和密码填入独立输入框，不要写在 URL 中。CipherNest 不接受 HTTP、证书错误或自动重定向。
3. 确认证书受设备信任、未过期，且覆盖地址中的域名或 IP。端口须实际提供 HTTPS；不能只凭端口号判断协议。

新的多设备同步使用普通 WebDAV 文件读写行为，不要求旧版 CN1 协议所需的强 ETag 或 `If-Match` 条件写入。CN2 的事件格式、合并与检查点规则见 [CN2 同步设计](SYNC_V2_DESIGN.md)。若已在此设备保存旧版 WebDAV 备份连接，设置同步时会预填其目录地址和用户名；两项完全一致时可以留空密码，沿用已保存的凭据。

## 创建与连接设备

1. 在第一台设备解锁保险库，打开“设置 → WebDAV 多设备同步”，选择“设置第一台设备”，输入目录、用户名和密码。成功后，应用会展示同步恢复码。请将它保存在 WebDAV 目录之外。
2. 在另一台设备选择“连接另一台设备”，输入同一目录、凭据和完整恢复码。核对远端概览后确认加入。本机已有条目或删除记录时，默认选择合并；选择以远端替换本机，需要再次确认。预览后若本机或远端内容变化，须重新预览。
3. 连接后，应用在保险库解锁期间，于解锁后、本机修改后及定期检查时自动同步。也可在设置中点击“立即同步”。锁定时不会启动新的同步检查。

恢复码是另一台设备解密同步数据所需的秘密，不能重置本地主密码。已配置设备可验证当前主密码后再次查看。不要把恢复码放在同一 WebDAV 目录。停止此设备的同步只清除本机配置，不会删除服务器文件或其他设备的配置。

同步会合并条目和删除记录。两台设备同时改动同一条目时，应用会保留待核对的冲突副本，并在设置中提供查看入口。网络或服务器故障不会撤销本机已保存的修改；若远端提交结果或本机状态待确认，请核对其他设备，并手动重试同步。服务器可能删除、隐藏或回滚数据，应用不能证明首次加入时看到的是最新合法版本；请与另一台可信设备核对概览，并定期导出独立的加密备份。

远端加密事件会持续占用 WebDAV 存储空间，目前不会自动清理。同步会传播删除，也不提供历史版本浏览和整库恢复，请保留独立介质上的 `.cnvault` 加密备份。

单个同步空间当前最多处理 40,000 个事件、累计 256 MiB 的加密事件和 16 MiB 的目录列表，最多连接 64 台写入设备。客户端会在上传前检查已读取的历史及待发事件；达到上限时停止写入。普通 WebDAV 无法让多台设备的容量检查原子化，接近上限时并发写入仍可能使空间超过读取限制。迁移时先在各设备导出加密备份并核对未同步修改，再用已核对的设备在新目录创建同步空间；其他设备使用新恢复码加入并选择合并。旧空间文件不会自动删除。

## 旧版同步与历史备份

已有 CN1 同步配置仍可在设置中的“旧版同步配置（CN1）”入口查看状态、恢复码并停止本机同步。新同步与旧版同步不会同时在一台设备上配置。迁移时先核对各设备数据，保存旧版恢复码和独立备份，再停止当前设备的旧版同步，创建或连接新的同步空间。旧版远端文件不会因此删除。CN1 协议的条件写入要求及安全边界见[旧版同步设计](SYNC_DESIGN.md)。

“设置 → 加密备份 → 历史 WebDAV 备份与恢复”保留旧版单向上传和历史恢复功能；锁定页也可选择远端备份恢复。启用新同步时，旧版备份的自动上传会关闭；保持同步连接期间不能重新启用，但手动上传和恢复仍可使用。备份按版本保存完整加密 `.cnvault` 文件，恢复时需要该文件创建时的主密码，并会整库替换本机，不会合并设备修改。旧版备份目录可以只支持普通 WebDAV 读写，不需要强 ETag 或条件写入。详情见[备份与恢复](BACKUPS.md)。

## 绿联 NAS 的端口与证书

绿联 WebDAV 的[默认端口](https://support.ugnas.com/detail/article/zh-CN/82)通常是 HTTP 5005、HTTPS 5006，但可在管理界面修改。以实际服务配置为准。

自签证书或证书中的地址不匹配时，CipherNest 会拒绝连接。通过 IP 连接时，证书须包含对应的 `iPAddress` SAN；通过域名连接时，证书须覆盖该域名。导入证书后，还需将它分配给 WebDAV 的 HTTPS 服务，并确认服务发出完整证书链。私有证书颁发机构的根证书也须受客户端系统信任。绿联的操作位置见[证书说明](https://support.ugnas.com/detail/article/zh-CN/107)和[WebDAV 说明](https://support.ugnas.com/detail/article/zh-CN/82)。

## 常见连接问题

| 现象 | 检查项 |
| --- | --- |
| HTTPS 失败或超时 | 核对地址、端口、网络、防火墙以及 WebDAV 服务是否实际启用 HTTPS。 |
| 证书错误 | 核对信任链、有效期，以及证书是否覆盖所用域名或 IP。 |
| 401 或 403 | 核对账号、应用专用密码及目标目录的读写权限。 |
| 404 或目录无效 | 确认目录已创建、路径大小写正确、地址以 `/` 结尾。 |
| 恢复码无法使用 | 确认使用同一同步空间的完整恢复码，并核对远端同步 ID。 |
| 旧版 CN1 提示不支持安全同步条件 | 检查旧版协议所需的强 ETag、`If-Match` 和 `If-None-Match`；新同步不要求这些条件。 |

同步状态和备份均可能受远端服务故障或人为删除影响。请定期将 `.cnvault` 导出到独立介质；导出文件不包含 WebDAV 连接配置和同步恢复码。
