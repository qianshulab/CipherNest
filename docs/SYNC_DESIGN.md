# 旧版 CN1 WebDAV 同步设计

本文记录旧版 CN1 / sync-v1 协议，供已有配置的用户和维护者参考。新的 WebDAV 多设备同步使用 CN2 协议和独立的加密 `.sync-v2` 本机配置，采用普通 WebDAV 文件读写及远端不可变加密事件，不要求 CN1 的强 ETag 或条件写入。CN2 仍需独立恢复码，合并条目与删除记录；远端事件目前不自动清理，也不提供历史版本浏览。使用步骤见 [WebDAV 使用指南](WEBDAV.md)。

状态：适用于 CipherNest 0.3.9 的旧版 CN1 **未审计 beta**
协议版本：CN1 / sync-v1

## 结论

旧版 CN1 WebDAV 同步的风险在下列边界内可以控制，但不能消除：

- 新建或加入的同步配置默认启用自动模式，在解锁、本地保存和定期检查时同步；旧版现有手动配置升级后保持手动。锁定态不会发起新的同步请求。若途中锁定，已经开始的密文请求可能收尾，但不得提交本地状态。
- WebDAV 只被当成通过 HTTPS 访问的**不可信密文对象存储**。服务器不参与解密、合并或密钥恢复。
- 同步使用独立随机生成的 256 位 Sync Root Key，编码进以 `CN1.` 开头的同步恢复码；它不由主密码派生。
- 远端保存不可变的认证加密 snapshot 和一个认证加密的可变 head，不上传活动中的 `vault.cnvault`。
- 客户端使用三方合并、墓碑和显式冲突副本，避免把并发写入静默处理成 last-writer-wins。

这里的端到端加密只表示 WebDAV 服务端没有正文解密密钥，并不等于“零知识”或“绝对安全”。恶意或故障服务仍能删除、延迟、回滚或隐藏合法密文，观察访问元数据，并造成拒绝服务；终端失陷时也可能读取解锁后的秘密。

## 用户可见行为

### 创建同步空间

用户提供一个已经存在的专用 WebDAV 集合 URL、用户名和应用专用密码。客户端先验证 URL 和集合能力，再：

1. 生成随机 `sync_id`、随机设备 ID 和 256 位 Sync Root Key。
2. 把当前条目与删除墓碑加密为第一个不可变 snapshot。
3. 创建指向该 snapshot 的加密 head。
4. 在本机保存加密同步 sidecar。
5. 向用户显示一次 `CN1.<sync-id>.<key>` 形式的同步恢复码。

同步恢复码是高价值秘密。取得它且能访问远端对象的人可以解密该同步空间的当前和历史 snapshot，也可以把自己的设备加入同步空间。它应离线保存，不能与 WebDAV 应用密码放在同一处。已配置设备可在重新验证主密码后再次查看该码。

### 加入已有同步空间

新设备需要 WebDAV URL、用户名、应用专用密码和完整 CN1 同步恢复码。客户端先认证远端 head/snapshot，再让用户预览远端条目数、更新时间和序号。后端同时保存一个 5 分钟有效、单次消费的不透明预览 token，绑定当前 vault/session、本地 generation、规范化端点、用户名、sync ID、snapshot 精确哈希和 sequence；不在 token 记录中保存应用密码或恢复码。确认加入时重新获取远端对象，只有上述绑定全部匹配才允许下载或首次合并；锁定、过期、token 重用、本地数据变化、切换保险库/会话或远端 head 变化都会失败并要求重新预览。首次合并若 head 在提交时发生并发变化也直接失败，不会自动把未预览的新版本应用到本地。

该机制防止用户“预览的是 A，实际应用的是 B”，不证明 A 是全局最新版本。首次加入仍属于信任首次使用（TOFU）：新设备没有以前保存的 checkpoint，仅凭恢复码无法证明服务器交付的是历史上的最新 head。

如果本地已有条目或删除墓碑，默认选择合并；“以远端替换本机”需要再次确认，后端也要求明确的替换标志。没有共同基线的首次合并会合并不相交的 ID；同一 ID 内容不一致时保留本地记录，并把远端记录保存为新的冲突副本。不会静默覆盖密码。

### 日常同步

手动模式由用户点击“立即同步”；自动模式使用同一套校验和合并规则进行解锁后的后台检查。客户端以本机保存的 base snapshot 做三方比较：

- 本地未变、远端已变：验证父链后应用远端内容。
- 本地已变、远端未变：提交新的远端 snapshot。
- 两端都变：三方合并后提交合并结果。
- 两端内容一致：只推进经验证的本地 checkpoint/状态。

本机条目保存、删除或收藏后，界面会提示待同步并重新读取本地同步状态。若状态读取失败，界面显示状态不明，不沿用旧的“已同步”结论。设置页按“同步冲突”标签统计待核对条目；若原条目已有 20 个标签，冲突副本保留全部原标签，改按标题末尾的“（同步冲突）”标记识别。用户可以编辑标签和标题；自行设置相同标记的条目也可能进入审阅列表。因此该数量是审阅入口，不是独立的冲突审计记录。

从远端应用或合并内容时，只替换条目与 tombstone；当前设备的安全设置、vault ID 和备份状态保持本地。写入前沿用正常持久化流程保留旧版本，提交后为新版本建立本机加密快照。网络请求进行期间若本地保险库、解锁 session 或同步 sidecar 发生变化，结果不会直接覆盖新状态；用户需要重新同步。每次解锁都会生成新的 session ID，因此“锁定后立即重新解锁”也不会让锁定前的网络任务恢复提交资格。

如果锁定发生在远端 PUT 已发送之后，远端 head 可能已经成功前进，而本机因锁定拒绝保存新的 checkpoint。这不会向锁定 UI 交付明文；下次解锁时，客户端仍须从旧 checkpoint 验证远端后续父链，无法确认时自动模式会暂停，要求用户核对并手动同步。

### 可选自动同步

新建或加入同步空间时，自动模式默认启用；旧版已有配置保持手动，直到用户在“设置 → 多设备加密同步”开启。用户也可随时关闭自动模式。启用后，解锁及本地成功保存会在约 3 秒后安排检查，连续修改会合并触发；保险库持续解锁时约每 90 秒检查一次远端。后台检查不延长自动锁定时间，锁定或停用同步会取消后续检查。手动同步优先于后台检查。

临时网络失败会显示警告，并在解锁期间的后续检查中重试。若本地检查点、远端认证历史或远端提交结果无法安全确认，自动模式会暂停；用户应保留本机备份，核对其他设备状态后执行手动同步。成功完成手动同步后可恢复自动检查。自动模式使用相同的三方合并与冲突副本规则，不能代替独立备份。

整库备份恢复会清除当前 CN1 同步配置及检查点，即使恢复的是同一保险库。继续使用同步需要重新加入，预览并核对远端数据。重新加入从新的首次信任状态开始，不能作为跳过检查点异常的无风险操作。

停止当前设备同步只删除这台设备上的同步配置，不删除远端对象，也不撤销其他持有恢复码的设备。

## 密钥与数据分离

### 本地保险库

本地 `vault.cnvault` 继续由主密码路径保护：主密码经 Argon2id 派生 KEK，KEK 包裹随机 256 位 Vault Root Key（VRK），VRK 再保护保险库正文。锁定文件仍允许攻击者离线猜测主密码。

### 同步空间

同步使用另一把随机 256 位 Sync Root Key。HKDF-SHA-256 以 `sync_id` 和不同用途标签分别派生 snapshot 与 head 的密钥，再使用 XChaCha20-Poly1305 和随机 nonce 进行认证加密。同步 snapshot 与 head 密文不是主密码校验器；仅取得这些同步对象和反编译后的程序，不会把高熵同步密钥降级成主密码猜测问题。完整 `.cnvault` 备份仍允许攻击者离线猜测弱主密码。

### 本机同步 sidecar

活动 sidecar 为：

```text
<应用数据目录>/vault.cnvault.sync
```

它包含 WebDAV URL、用户名、应用专用密码、同步根密钥、设备 ID/计数器、最后接受的 checkpoint、用于三方合并的 base snapshot、本地 generation、最后同步时间，以及自动模式、暂停与警告状态。整个内容以从当前 VRK 和 `vault_id` 经 HKDF 派生的独立密钥进行 XChaCha20-Poly1305 认证加密，并使用原子私有文件写入。

同步提交、VRK 轮换或恢复事务中可能短暂出现 `.sync.next`、`.sync.restore-hold` 等恢复候选；它们仍是由相应 VRK 保护的认证密文，不能当作独立便携备份。sidecar 外层格式、版本、vault ID、nonce 和密文长度不是秘密。

因此普通静态文件复制不会直接暴露 WebDAV 密码或同步根密钥；但能解锁本地保险库的人、已控制解锁进程的恶意软件，或成功离线猜出弱主密码的攻击者，也能到达这份同步状态。更改主密码轮换 VRK 时，sidecar 会在新 VRK 下重新加密；恢复另一个保险库时，旧同步配置不会自动绑定到新库。

这里的“重新加密 sidecar”不是同步凭据轮换：共享 Sync Root Key、WebDAV 应用密码、sync ID 和远端不可变历史都保持不变。被攻击者复制的旧保险库/旧 sidecar 组合，在其保护凭据后来被攻破时，仍可能暴露继续使用中的同步根密钥和应用密码。怀疑设备、本机旧数据、应用密码或恢复码泄漏时，必须在 WebDAV 服务端撤销旧应用密码，并从可信设备创建全新的同步空间与 CN1 恢复码后迁移；只更改主密码或停止本机同步不够。

### 不进入远端同步对象的本地数据

同步 snapshot 只包含条目和删除墓碑。以下内容不会进入远端同步对象：

- 主密码、Argon2 KDF 参数或 salt。
- 本地 VRK、主密码 key-wrap 或完整 `vault.cnvault` envelope。
- 本地安全设置、`last_backup_at` 等保险库设置。
- 旧版 `.devices`、`.device-auth` 或其他设备认证记录。
- WebDAV URL、用户名、应用密码以及本机保存的 checkpoint/base sidecar。用户名和应用密码会作为 HTTPS 认证信息发送给用户配置的 WebDAV 服务器，但不会写入 snapshot/head。

## 远端对象格式

一个同步空间在指定 WebDAV 集合中使用扁平文件名：

```text
ciphernest-<sync-id>-snapshot-<sha256>.cnsnap
ciphernest-<sync-id>-head.cnhead
```

snapshot 文件名中的 SHA-256 是对**加密对象精确字节**计算的哈希。snapshot 明文在客户端加密前包含协议版本、sync ID、递增 sequence、父 snapshot 哈希、设备 ID/计数器、创建时间、完整条目和墓碑。head 的认证加密正文只指向当前 snapshot 哈希及 sequence。

安全更新流程是：

1. 用 `If-None-Match: *` 写入内容寻址的不可变 snapshot。
2. 重新读取并核对 snapshot 精确字节及 SHA-256。
3. 用上次读取到的**强 ETag**和 `If-Match` 比较并交换 head。
4. 重新读取 head，验证内容和 ETag 已变化。

并发客户端若同时更新 head，只有一个条件请求成功；另一个收到 precondition failure 后必须重新拉取并合并。条件请求语义来自 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)，WebDAV 集合和 `PROPFIND` 行为来自 [RFC 4918](https://www.rfc-editor.org/info/rfc4918/)。

AEAD 防止不知道同步根密钥的服务器伪造可接受的内容；SHA-256 名称和父哈希链绑定不可变历史；强 ETag/`If-Match` 处理正常并发。三者解决的问题不同，不能互相替代。

## WebDAV 连接要求

配置只有满足以下条件才会启用：

- URL 必须是 `https://`，包含主机、以 `/` 结尾，且不允许在 URL 中嵌入用户名/密码、query 或 fragment。
- URL 必须指向已经存在的 WebDAV collection；应用不会替用户创建目录。
- 客户端拒绝 HTTP 重定向，要求至少 TLS 1.2，并使用系统信任根验证服务器证书。
- 连接和每次提交前会在该集合中创建随机探测文件，验证 `If-None-Match: *`、错误 `If-Match`、强 ETag 和精确读取。收到拒绝写入的 `412` 后重新读取，确认文件和 ETag 均未改变；再让两个持有同一强 ETag 的 `If-Match` 写入并发竞争，要求恰有一个成功、另一请求失败，获胜内容和新强 ETag 必须匹配。最后用普通 `DELETE` 清理并确认文件消失。行为不满足即拒绝同步。
- 请求使用 `Cache-Control: no-cache, no-store`，要求中间缓存重新验证读取，并避免缓存保险库流量。
- 客户端用 HTTP Basic authentication 发送用户名和应用密码。Basic 本身不提供机密性，安全性依赖经过验证的 HTTPS；相关定义见 [RFC 7617](https://datatracker.ietf.org/doc/html/rfc7617.html)。

建议为 CipherNest 创建独立目录和最小权限的应用专用密码，不要复用账号主密码。自签名、被企业代理替换但未受系统信任、忽略条件请求、只返回弱 ETag 或重写对象的服务器会被拒绝。能力探测减少兼容性误判，但不能证明服务端以后始终正确，也不等于完整互操作或安全审计。

## 合并和删除规则

同步以稳定随机条目 ID、每条记录 revision 和 tombstone 为基础。日常同步比较共同 base、本地和远端：

- 只有一端相对 base 变化时采用变化的一端。
- 两端把同一条目改成不同内容时，保留本地条目，并将远端版本复制为新 UUID，标题/标签标记“同步冲突”。
- 一端删除、另一端修改时，保留原 ID 的 tombstone，并将修改版保存为新 UUID 的冲突副本。
- 两端都删除时保留一个有效 tombstone。
- 记录从集合中无故消失但没有 tombstone 时视为无效数据，不把“缺失”猜成删除。

这些规则以不丢密码为优先，代价是用户可能需要人工检查冲突副本。设备时钟只用于展示和记录时间，不被当作决定覆盖关系的唯一依据。

## 回滚、分叉与 checkpoint

仅靠认证加密不能证明服务器返回的是“最新”合法密文。CipherNest 在本地加密 sidecar 中保存最后接受的 snapshot 哈希和 base snapshot。后续同步要求远端 head 沿父哈希链在最多 256 个 snapshot、总计最多 90 秒的检查预算内回到该 checkpoint；回不到就以回滚、分叉、缺失父快照或链过长失败关闭。验证器每次只保留当前链接、已见哈希集合和少量计数信息，并在检查完一个完整祖先 snapshot 后立即释放它；内存不会按“snapshot 最大体积 × 链长”累积，但仍需容纳单个受大小上限约束的远端对象及其解密结果。

这一机制有明确限制：

- 只有已经保存 checkpoint 的设备才能据此检测服务器回滚或向它展示不相干分叉。
- 全新设备首次使用恢复码加入时没有旧 checkpoint，是 TOFU，不能证明看到的是全局最新 head。
- 如果攻击者把**整个本地应用数据**同时回滚，保险库和加密 sidecar 中的 checkpoint 可能一起退回，检测也可能被绕过。
- 恶意服务器可以延迟最新写入、拒绝返回父对象、让检查超过 256 个 snapshot/90 秒或完全离线；客户端只能拒绝继续，不能强制服务恢复可用性。
- 没有外部透明日志、可信单调计数器或多设备 gossip，因此不承诺在所有情形下发现服务器 equivocation。

## 共享恢复码与设备撤销

CN1 v1 是个人同步协议，所有设备共享同一 Sync Root Key。当前没有逐设备签名密钥、设备授权日志或密码学撤销：

- 从当前设备“停止同步”只移除本地配置。
- WebDAV 端撤销某个应用密码可以切断该凭据的服务器访问，但不能让设备忘掉已经取得的同步根密钥、历史密文或明文。
- 恢复码泄漏或设备丢失且可能泄密时，安全做法是撤销 WebDAV 凭据、创建全新的同步空间和恢复码，并让仍可信设备迁移；旧远端历史仍应视为已泄露给持码者。
- 如果没有任何仍配置的设备且同步恢复码也丢失，就不能把新设备加入该空间。该码不能重置本地保险库主密码。

## 元数据与保留

远端正文经过认证加密，但 WebDAV 服务及其网络观察者仍可能看到或推断：

- 账号、来源 IP、TLS 连接目标、请求时间和流量模式。
- sync ID、head/snapshot 文件名、对象数量、大小、创建/更新时间及 ETag。
- 同步发生频率、历史增长和设备活动的大致模式。

设备 ID、条目内容、记录数和 snapshot 内时间位于密文中；远端对象外层的格式、版本、随机 nonce 和密文长度不是秘密。每次 snapshot 是完整内容，密文大小仍可能泄露大致规模。0.3.9 不做长度填充，也不会自动垃圾回收远端不可变历史；提供商的版本历史、备份和删除保留政策同样不受应用控制。自动模式会增加请求频率，使设备活动时间更容易被推断。

## 仍然存在的攻击面

即使协议按预期工作，以下风险仍然成立：

- **删除、延迟、回滚与 DoS**：服务端或账号攻击者可删除 head/snapshot、耗尽配额、拒绝请求或隐藏最新内容。同步不能替代独立备份。
- **终端失陷**：已解锁进程中的恶意软件、调试器、键盘/剪贴板记录、屏幕抓取或恶意更新可取得条目、主密码、恢复码或 WebDAV 凭据。
- **共享密钥泄漏**：任何拿到 CN1 码且能取得远端对象的设备都能解密整个不可变历史；v1 没有单设备密码学撤销。
- **凭据和服务风险**：WebDAV 服务在 TLS 终点会看到账号凭据；账号找回、运营日志、服务器漏洞和供应链均在新的攻击面内。
- **解析和资源消耗**：客户端对 URL、XML、对象和记录设置上限并严格验证，但未经过大规模 fuzzing 或独立审计。
- **能力探测不是认证**：当前探测只能确认该集合在当次请求中表现出所需的 ETag/条件请求语义，不能证明服务以后一直诚实，也不能替代真实服务端互操作测试；0.3.9 尚未完成至少一个真实提供商的三平台端到端验证。
- **操作错误**：覆盖错误目录、丢失恢复码、误把“停止本机同步”理解为远端删除，仍可能导致不可恢复后果。

## 安全使用建议

1. 只有确实需要多设备编辑时才启用同步；单设备用户可以一直保持关闭。启用自动模式前确认服务端配额和各设备的备份策略。
2. 使用可信、及时更新的 WebDAV 服务，创建专用目录和可单独撤销的应用密码。
3. 把 CN1 恢复码离线保存，并与 WebDAV 应用密码分开；不要截图、发聊天消息或长期留在剪贴板。
4. 每台设备启用全盘加密、短自动锁定并及时安装系统与 CipherNest 更新。
5. 继续定期导出 `.cnvault` 到异盘或离线位置并实际验证恢复。WebDAV 历史不是备份承诺。
6. 同步冲突后检查所有带“同步冲突”标记的副本，再决定保留或删除。
7. 恢复码、WebDAV 应用密码、设备或本机旧数据可能泄漏时，先撤销旧 WebDAV 应用密码，再迁移到新同步空间与新恢复码；不要把更改主密码或“停止同步”误当成远端密钥撤销。

若一台设备离线太久，远端相对它的 checkpoint 已前进超过 256 个 snapshot，或父链验证累计超过 90 秒，同步会失败关闭。不要为消除报错直接删除本地配置并盲目重新加入：先导出当前本地加密备份，在仍可信且较新的设备上确认远端状态，再决定合并或重新加入。重新加入会重置该设备的历史锚点，属于一次新的 TOFU 决策。

每个保险库最多容纳 20,000 条删除墓碑，当前版本不会自动清理。达到上限后新删除被拒绝。先导出并验证备份，再规划新保险库及同步空间的迁移，逐台核对条目和冲突副本；不要直接编辑本地加密文件或删除远端历史对象。

## 当前版本未包含

- CipherNest 托管账号或同步服务器。
- 推送通知或锁定态发起的新同步请求。
- 逐设备端到端授权、签名、撤销或密钥轮换。
- 条目/保险库共享、团队权限、附件、服务端搜索或可搜索加密。
- 远端不可变 snapshot 的自动垃圾回收或安全删除。
- 外部透明日志、可信时间戳或全局最新性证明。

这些限制是 0.3.9 beta 的协议边界。
